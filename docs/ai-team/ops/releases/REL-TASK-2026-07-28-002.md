## Summary

WorkPilot now includes a dedicated **Gmail AI Employee** template. When that employee is ACTIVE, Gmail inbox sync assigns drafts, tasks, and approval work to it instead of an arbitrary first ACTIVE employee.

## What's included

- New Studio template: `gmail_ai` — Gmail Inbox Specialist
- Sync preference: Gmail → prefer ACTIVE `gmail_ai`, else first ACTIVE (legacy)
- Settings → Email guidance for connecting Gmail and creating the Gmail AI Employee
- Approval / no-auto-send behavior unchanged

## What's not included (deferred)

- Real Gmail compose/send API calls (stubs remain)
- `EmailConnection.employeeId` FK (no migration in this release)
- Dedicated Gmail inbox application page
- Outlook-specific employee template

## How to use

1. Open **AI Employees → Studio** and create employee from **Gmail AI Employee**
2. Activate the employee
3. Open **Settings → Email** and connect Gmail
4. Sync — sensitive intents still require approval before send

## Verification

- Registry lists `gmail_ai` as available
- Preference unit tests cover Gmail prefer / Outlook first-ACTIVE
- Existing Phase 7A email provider tests preserved

## Risks

- Orgs with multiple ACTIVE employees and no `gmail_ai` keep previous first-ACTIVE behavior
- Compose to Gmail network still stubbed — operators must not assume external send
